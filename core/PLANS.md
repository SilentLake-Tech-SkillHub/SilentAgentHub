# PLANS.md

> 本文件定义复杂任务的执行计划规范。具体任务计划默认写入 `任务管理/执行计划/<日期>_<任务名>.md`。执行计划是 living document，必须随执行过程持续更新。

## 1. 何时必须使用执行计划

以下情况必须创建或更新执行计划：

- 跨模块开发。
- 设计 + 前端 + 后端 + 数据 + AI 联动。
- 新增复杂功能。
- 架构调整、重构、迁移。
- Debug 涉及多个系统或无法一次定位原因。
- 数据仓库、指标体系、ETL、RAG、Agent 行为等复杂链路建设。
- 用户明确要求 plan、方案、执行计划、分阶段推进。

## 2. 执行计划的基本原则

每个执行计划必须满足：

- 自包含：只看这个计划，也能知道任务背景、目标、路径、文件、验证方式。
- 可执行：必须写清楚要改什么、在哪里改、怎么验证。
- 可更新：每次推进后必须更新 Progress。
- 可复盘：必须记录关键决策、意外发现、最终结果和剩余问题。
- 可恢复：中断后，新的 Agent 或人类可以从计划继续。

## 3. 执行计划模板

创建具体计划时，使用以下结构。

```md
# <任务名称>

本执行计划遵循根目录 `PLANS.md`。本文件是 living document，执行过程中必须持续更新 Progress、Decision Log、Surprises & Discoveries、Validation、Outcomes & Retrospective。

## 1. Purpose / 目标与用户价值

说明这个任务为什么重要。完成后用户、产品、工程或数据系统会获得什么能力。说明如何观察这个能力确实生效。

## 2. Current Context / 当前上下文

说明当前已有状态：

- 当前项目结构
- 相关文件路径
- 相关模块
- 当前问题或需求
- 已知约束
- 待确认事项

不要依赖“前文已经说过”。需要的上下文应写入本计划。

## 3. Scope / 范围

### In Scope

列出本次要做的内容。

### Out of Scope

列出本次不做的内容，避免范围漂移。

## 4. Progress / 进度

使用复选框记录真实进度。每次停止、切换阶段或完成子任务都必须更新。

- [ ] <待完成事项>
- [ ] <待完成事项>

## 5. Plan of Work / 工作方案

用自然语言说明实施路径。涉及文件时必须写完整路径。涉及模块时必须说明模块关系。涉及技术方案时必须说明选择原因。

## 6. Concrete Steps / 具体步骤

写清楚实际执行动作，例如：

1. 检查 `xxx`。
2. 修改 `xxx`。
3. 新增 `xxx`。
4. 运行 `xxx`。
5. 记录 `xxx`。

## 7. Validation / 验证方式

列出必须验证的内容：

- 代码验证
- 前端验证
- 后端验证
- 数据验证
- AI eval
- 手工验收

每项验证必须写清楚命令、预期结果、无法验证时的替代方式。

## 8. Decision Log / 决策记录

每个关键取舍都必须记录：

- Decision: <做了什么决定>
  Rationale: <为什么>
  Impact: <影响范围>
  Date/Author: <日期/执行者>

## 9. Surprises & Discoveries / 意外发现

记录执行过程中发现的异常、隐藏依赖、重复问题、数据问题、测试问题或架构问题。

每条发现都要说明是否已写入 `任务管理/问题流水.md`。

## 10. Risks & Blockers / 风险与阻塞

记录当前风险和阻塞：

- 风险描述
- 影响范围
- 处理方式
- 是否需要用户决策

## 11. Issue Ledger Sync / 问题流水同步

列出本计划关联的问题编号：

- ISSUE-0001：<问题摘要>

## 12. Outcomes & Retrospective / 结果与复盘

阶段结束或最终完成时填写：

- 实际完成内容
- 未完成内容
- 验证结果
- 经验教训
- 是否需要补充 root 规则、模块规则或 Skill
```

## 4. 执行规则

- 计划创建后，不得只放在那里不更新。
- 只要需求明确、依赖可获得、风险可控，执行计划应持续推进，不得无故停下询问是否继续。
- 每次发现问题，必须同步到 `任务管理/问题流水.md`。
- 每次改变方向，必须更新 Decision Log。
- 每次完成阶段，必须更新 Progress 和 Validation。
- 最终交付前，必须填写 Outcomes & Retrospective。
- 当上下文即将耗尽、剩余上下文低于 `5%` 或需要跨窗口继续时，必须先更新 Progress、Risks & Blockers、Issue Ledger Sync 和下一步动作。
- 如果计划中的规则与 root `AGENTS.md` / `CLAUDE.md` 冲突，以 root 规则为准。
