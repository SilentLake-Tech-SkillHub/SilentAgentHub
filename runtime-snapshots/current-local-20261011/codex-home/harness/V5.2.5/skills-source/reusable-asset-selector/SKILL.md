# Reusable Asset Selector

1. Search routed project assets, neighboring repositories, packages, templates, component libraries, scripts, knowledge records, and approved historical snapshots.
2. Evaluate goal fit, license, provenance, maintenance, security, compatibility, test evidence, customization cost, and ownership.
3. Classify each candidate as `reuse`, `adapt`, `reference only`, or `reject`, and record the reason in `代码管理/可复用模块选型记录.md`.
4. For selected assets, record source, version or commit, integration boundary, local modifications, validation, and upgrade strategy.
5. Update architecture, module plan, Plan, risks, and acceptance criteria.

Never reuse secret-bearing, unlicensed, unverifiable, or stale assets merely because they are faster to copy.
