# Requirement Clarification

## Clarify

1. Read the user request, comments, replies, attachments, existing product records, and current implementation as one requirement set.
2. State the user-visible result, target users, problem, in-scope behaviors, exclusions, supplied materials, dependencies, delivery stage, and acceptance evidence.
3. Resolve contradictions by quoting or precisely locating the competing requirements. Ask only for decisions that materially change the result.
4. Classify each candidate requirement in `产品管理/需求变更记录.md` as `做`, `Waitlist`, `不做`, or `需澄清`, with reason and source.
5. Once a requirement enters development, create or update its separate item in `流程管理/需求与范围变更记录.md` and track engineering status there.
6. Update `产品管理/需求澄清.md`, acceptance criteria, and the Plan before engineering begins.

Never use the product demand pool as a development-status ledger, and never silently treat a comment as unresolved after it has already been incorporated into the candidate solution.
