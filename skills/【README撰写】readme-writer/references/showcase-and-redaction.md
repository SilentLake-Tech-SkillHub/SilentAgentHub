# 图文展示与打码

## 每产物一图原则

- 展示区每个产物类型必须配"真实截图 + 一段说明文字"。纯文字展示区是半成品。
- 说明文字结构：产物名加粗 + 它展示的功能点 + 用户什么时候用它。
- 截图统一存目标项目 `docs/images/`，命名 `showcase-NN-产物名.png`（NN 与产物编号对齐）；无编号体系的用 `showcase-产物名.png`。

## 截图来源优先级

1. **现成页面**：项目里已有的 HTML 成品，浏览器打开直接截。
2. **渲染补拍**：md/数据文件转成 GitHub 风格 HTML 后截（本地起 HTTP 服务中转，不直接开 file://）。
3. **实景翻拍**：Finder/终端等系统界面截图，裁掉桌面、菜单栏、无关窗口。
4. **示意生成**：前三种都不行时才允许，图注必须写明"示意图"。

截图统一视口宽度（建议 1280px），高度按内容裁，不超过一屏半。

## 必须打码的内容

- 人名（讲师、同学、客户、作者本人）
- 邮箱、账号名、手机号、学号/工号
- 课程代码、客户代码、内部项目代号
- 本机绝对路径（/Users/xxx、/Volumes/xxx）
- 组织敏感名（未公开的部门、小组、服务器名）
- 真实成绩、分数（示例分数除外）

## 打码方式与优先级

1. **渲染层替换**（首选）：生成 HTML 时把敏感词替换为黑块字符（██████），适合文字型页面。注意：若替换发生在 HTML 转义之后，会把标签显示成原文——替换必须在纯文本阶段完成，替换后再做 HTML 转义。
2. **图像模糊**：对已生成的位图，用高斯模糊盖住目标区域。
3. **裁剪**：把敏感区域整块裁掉（Finder 截图优先裁剪掉整个侧边栏/菜单栏）。

## 打码验证（强制）

- 每次模糊打码后**必须目检回看**：把打码区域裁出来放大确认盖对了位置；发现糊错行（盖住了相邻的正常内容）立即从原图重来，不在错图上修补。
- 打码完成后整图通读一遍：还有没有漏网的敏感词（第二处、第三处同名信息）。
- 正文里不写"已打码"、"涉及隐私已处理"之类的说明；如需向读者解释图片为何有黑块，由用户决定是否加一句中性说明。

## 打码记录

多处打码时维护一份坐标/替换记录（哪个文件、哪个区域、盖了什么），发布前对照记录做最终复查，防止重新导出图片后漏打。
