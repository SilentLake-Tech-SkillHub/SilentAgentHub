# 框架与逐节迭代

## 框架先行

先只给章节骨架，用户确认或调整后才写正文。框架错了，正文写得再好也是返工。

### 默认框架（技能包 / 工具类）

1. **这是什么？**——出身故事钩子（用户原话优先）+ "它能帮你"能力清单（每条一个具体动作 + 一个用户收益）。
2. **最终成品是什么？**——产物表格（产物 / 里面是什么 / 什么时候用）+ 每个产物一张真实截图配一段说明。
3. **我应该准备什么材料？**——压到最少，理想是"三步上手"句式；每步一个动词开头。
4. **我可以在哪些工具上使用？**——兼容生态：名称+官方图标；安装双路径（AI 安装推荐 + 手动安装）；手动安装写清每工具的具体路径（用户根目录还是项目根目录、放好后的完整路径长什么样）。
5. **使用技巧**——固定两分法：① 怎么指挥 AI（单次使用 / 定时任务等模式）；② 每类产物怎么用（逐产物给使用时机和打开方式）。
6. **FAQ**——预判用户疑问 3-5 条，一问一答；末尾附"边界"声明（做什么、不做什么）。
7. **附录：文件结构**——目录树 + 每个文件一句话职责。

### 变体

- **库 / SDK**：1 这是什么 → 2 Quick Start（可运行代码块优先）→ 3 API 概览 → 4 示例 → 5 兼容性与依赖 → 6 FAQ。截图让位于代码块。
- **网站 / 产品**：1 这是什么 → 2 界面截图（首屏最有说服力）→ 3 核心功能逐个图文 → 4 技术栈 → 5 本地运行 / 部署 → 6 FAQ。
- **内部系统**：弱化营销，强化"入口、权限、运行方式、排障"。

变体只是章节替换，门禁与迭代协议不变。

## 逐节迭代协议

- **一次一节**：草稿一节 → 给用户 → 收修改方向 → 改到用户确认 → 下一节。用户说"继续"即进下一节。
- **用户素材优先**：用户给的口语文案（故事、清单、口吻）尽量原样采用；润色限于错别字、标点、格式，不改语气和用词习惯（"救你于水火之中"这类表达保留）。
- **删除要同步**：用户在某节删掉某个表述后，全文搜索该表述，其余节同步删除或改写。
- **矛盾要上报**：发现两节表述冲突（能力承诺 vs 边界声明），列出冲突请用户裁决，不自行改一边。
- **草稿不落盘？** 每节确认后即写入目标 README 文件，保持"文件里永远是已确认内容的最新拼合"，最后整篇预览。

## 动笔前拼写自查

把将出现的专有名词列出来逐个核对一遍：产品名、平台名（BlackBoard/Canvas、Google/Alphabet 系）、工具名、公司名。同类易混词重点查：Canva↔Canvas、GitHub↔GitLab、SilentLake↔SlientLake 这类拼写镜像错误。
