# Intake and evidence

Use this reference when the request starts, when sources conflict, or when a new claim is proposed. Keep the ledger in the current person's private workspace, not in the Skill package.

## Establish the job and material boundary

Confirm the target role, seniority, hiring region, language, application type, target length, and whether Word and PDF are both required. Ask which earlier resume is actually accepted and whether any draft, comment, or older version is out of scope. Inspect the project rules and source restrictions before opening files. Do not read folders explicitly marked off-limits.

When a visual reference is supplied, record observations separately from the candidate's facts: company-row treatment, icons and provenance, typography, page balance, density, narrative sequence, and writing syntax. State what is useful and what should not carry over. Avoid treating a reference person's achievements as evidence for the current person.

## Private claim ledger

For each proposed claim, retain enough to answer:

| Field | Question |
|---|---|
| Source | Which authorized document or statement supports it? What exact passage or user confirmation? |
| Ownership | What did this person decide, build, lead, contribute, or merely observe? |
| State and date | Is it launched, used, in progress, planned, or an experiment? When was that true? |
| Measure | What is the unit, baseline, denominator, period, sample, and attribution of a number? |
| Destination | Which language, role variant, module, and candidate version may use it? |
| Confidence | Verified, user-confirmed, conflicting, or awaiting confirmation? |

Do not turn a team outcome into individual ownership, a prototype into a launched product, an estimate into a measured result, or a missing number into a rounded claim. When sources disagree, show the competing wording and the sentence affected; ask the smallest question that resolves the decision. Leave unresolved claims out of a deliverable.

## Section checkpoint

For each module, present the evidence used, what was retained or omitted and why, the proposed resume wording, and the exact decision requested. Record “approved,” “revise,” or “defer” for that module. Approval of one module does not approve another module, another language, Word layout, or PDF export. Material changes to an approved module reopen it and downstream file approvals.
