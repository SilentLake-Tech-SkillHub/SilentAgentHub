# 人工注册与维护清单

## 首次接入必须人工完成

| 工作 | 责任人 | 完成证据 | AI 能否代做 |
|---|---|---|---|
| 注册并完成企业支付宝认证 | 法人/管理员 | 企业主体名称、账号状态 | 否 |
| 开通商家平台并确认 PID | 账号管理员 | PID 与公司主体一致 | 只读协助 |
| 创建网页/移动应用 | 开放平台管理员 | APP ID、应用状态 | 需人工确认 |
| 签约电脑网站支付 | 商务/管理员 | 产品状态有效 | 否 |
| 配置 RSA2 密钥 | 开放平台管理员 | 应用公钥已上传、支付宝公钥已下载 | 最终上传/下载人工完成 |
| 配置 HTTPS 应用网关 | 开放平台管理员 | 网关保存成功 | 可协助填写，需人工确认 |
| HTTP 订阅退款冲退消息 | 开放平台管理员 | `alipay.trade.refund.depositback.completed` 为 HTTP | 需人工确认 |
| 获取沙箱买家账号并登录付款 | 测试人员 | 沙箱交易记录 | 账号密码必须人工输入 |
| 生产异账号小额付款 | 另一实名买家 | 交易号、账单和入账证据 | 必须单独授权 |

## 持续维护

| 频率 | 工作 | 验收 |
|---|---|---|
| 每月 | 下载交易账单并与内部订单/账本/额度对账 | 差异为 0 或有工单 |
| 每月 | 检查电脑网站支付签约、应用上线、HTTP 消息订阅 | 状态有效 |
| 每季度 | 轮换应用密钥并演练回滚 | 新旧密钥切换记录 |
| 每次发布 | 备份代码、环境文件、密钥挂载配置和数据库 | 可恢复备份路径 |
| 每次退款 | 双人或管理员审批，记录退款原因、金额和额度回收 | 支付宝退款状态与内部账一致 |
| 每次异常 | 保留 `out_trade_no`、`trade_no`、时间、错误码，不记录密钥 | 问题流水闭环 |

## 不能自动化的判断

- 商家和应用是否符合业务类目及监管要求。
- 收款主体、合同主体、开票主体和结算账户是否符合公司财务制度。
- 是否允许真实扣款、退款、关单或改动生产密钥。
- 历史订单迁移时旧 APP ID/PID/公钥保留多久。
- Alipay Global/Alipay+ 是否另行申请。
