# Platform checks before publishing

Recheck the live interface for every task. These checks are not permanent platform specifications or standing authorization.

## Account and source

- Use the repository named by the user and retain its verified source URL.
- Confirm the currently signed-in creator account before making changes. A public profile is only a comparison reference and does not prove account ownership.

## Editor behavior

- Inspect the current title and body limits, including how links and topics are counted. Some image-text and longform composers have different limits.
- Longform can convert text into images and flatten tables into separate lines. Inspect the rendered result for lost column/row relationships.
- Automatic summaries may introduce wording absent from the source. Disable them if possible or review their full output before publishing.
- Typing a hashtag can leave plain text; use topic selection and verify registered, clickable topics on the final post.
- Verify whether a draft is stored locally or on the platform. Report the actual save status; do not promise availability on another device without evidence.
- A scheduling field alone does not prove successful scheduling. Verify the saved scheduled entry, including date, time, timezone and visibility.
- Inspect any visible IP attribution before publication, disclose an unexpected observed region, and do not treat it as evidence of the user's physical location.

## Content and image checks

- Derive selected sections, exact hook, image count and format from the current request.
- Preserve original screenshots separately when requested. Count original uploads separately from platform-generated longform pages.
