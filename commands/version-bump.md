执行版本升级，参数：`$ARGUMENTS`

## 版本号规则

解析参数中的升级类型（`x`、`y` 或 `z`）和变更描述：

- `z`：bug 修复、debug、小范围问题修正 → Z + 1
- `y`：新增或调整功能，未达到架构级变化 → Y + 1，Z 归零
- `x`：架构迭代、重大重构、系统级升级、核心模块重组 → X + 1，Y 和 Z 同时归零

## 执行步骤

1. 读取当前项目根目录或 `项目建设/` 下的 `版本控制.md`，找到当前版本号。
2. 按规则计算新版本号。
3. 更新 `版本控制.md`，在版本历史中追加新记录，格式：

```
## vX.Y.Z — YYYY-MM-DD
- 变更内容：[变更描述]
- 影响范围：[受影响的模块或文件]
- 升级类型：[功能新增 / bug修复 / 架构迭代]
```

4. 如果是 X 大版本升级，还需要：
   - 提示用户将当前代码存档到新目录，命名格式为 `代码仓_X.0.0`

## 完成后

输出：旧版本号 → 新版本号，以及已更新的版本记录内容。
